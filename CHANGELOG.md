# Changelog

## Unreleased

- New (not used by the tools yet): owner parts (O2.1). `UiPart` with `createUiPart`, `reviseUiPart` and `renameUiPart`; `partName` re-exports the slug rule of `@punyts/stateui-app/core`; the `UiPartRepository` port (`create`, `findByName`, `findById`, `list`, `write`, `delete`, `rename`) and its in-memory fake `InMemoryUiPartRepository` in `src/testing/`. `UiBuilderPorts` takes an optional `parts` beside `repository`.
- `ui_command` takes `navigate` with a screen name as `target` and the params as an object `value` (a screen the app does not have is `unknown-screen`, with the screens it has), and component commands on screen nodes (`screens.home.children.list`). The preview host passes a `navigate` target through without the `$.` prefix.
- Server logic runs `navigate`: `AppLogic` gives the engine the document's screens and resolves `^key` in the current screen (`$.route.screen` on the authority) before the shell; guards also cover `$.screens` and `$.route`.
- New (no tool yet): component search in the catalog. `ComponentCatalog.search({ need, category?, tier?, limit? })` ranks components with the shared BM25 engine of `@punyts/stateui-app/core` over their purposes, name words, summary, and property and event names. It returns `{ results: [{ name, category, tier, summary, matched, example }], weak, categories? }` and is never empty: below `WEAK_SCORE_FLOOR` (4.9) the result is `weak`, and a need with no match gets the category index and the entries of the category nearest the need by letter trigrams (or of the asked `category`). `limit` defaults to 5, capped at 20; an unknown `category` or `tier` throws `InvalidSearchArgumentError` naming the allowed values. `categoryIndex()` lists each category that has members with its count and three typical members. The catalog loader now refuses a `catalog.json` without `category` and `purposes` and says to rebuild `@punyts/stateui-components`. `ui_components_list` and `ui_component_get` are unchanged; `ui_components_search` replaces the list tool once the baseline runs are recorded.
- New: the search-first measurement kit. `test/measurement/requests.md` holds the three requests (store, finance dashboard, booking app) with their checklists and how to run a build; `test/measurement/needs.json` lists 26 needs in plain words with the component that should be found; `scripts/summarizeToolLog.mjs <calls.jsonl>...` prints catalog tokens read, failed writes and first-write validation errors per build, and the median and range over several. Run logs go in `.measurements/` (ignored).
- New: `--tool-log <file>` (`STATEUI_MCP_TOOL_LOG`, and `toolLog` of `startServer` and `createServices`) appends one JSON line per tool call: `{ at, tool, ok, errorCode?, requestChars, responseChars, target?, errorCount?, warningCount? }`, for measuring how agents use the tools. Arguments and response bodies are never written. A failed append is reported once and never fails the call. The port is `ToolCallLog`, the adapter `FileToolCallLog`.
- Fix: the file sweep no longer deletes a file that only the running state holds when the server has a statenet or the app is Persisted. It searched `app.json` and `state.json`, and with a statenet no `state.json` is written, so a `fileField` value set in a view was removed on the next upload 24 hours later. The sweep now reads the state through the app repository (what `ui_state_get` returns) in every mode, and keeps every file when the app or its state cannot be read. `$.server` is not part of that state, so a file referenced only there is not kept. `UiFileRepository.findUnreferenced` is replaced by `findOlderThan`; `isFileReferenced` is the one definition of a referenced file.
- Fix: a `ui_app_write` that changes the document's `data` writes those changes into the running state at the paths that changed (no guard asks, no rule fires), so open views show them without `ui_state_reset`; the rest of `$.data` keeps what users and tools changed.
- New: `ui_screenshot` takes `fullPage: true`: the viewport grows to everything the app can scroll to, in its document or a scrolling element of a component, up to 16000 px, measured again as the view grows. Page captures only.
- Fix: `ui_component_get` returns the component's `tokens` (path, type and default, such as `image.fill`); the catalog had them but the entry dropped them, though the instructions sent agents there for component token names.
- Change: the server instructions say that rules and tables wait for the results of rules and tables, that a unit runs after the units that write under its trigger, and that `on` commands take `from`.
- Fix: a document write that adds or replaces a node, changes a node's `component` or adds, changes or removes a `<-` link reaches an open view as a write of the whole node, which the runtime mounts live (component defaults, composed components and links), instead of a load or a plain store write. A plain write left the node half-mounted: a `stat` swapped for a `panel` reported "Binding or controller of runtime failed at $" and a new node's `<-value` stayed unlinked ("—"). A change that belongs to the root node, or to theme, locales or composed, is still a load.
- New: `ui_state_get` reads the state live: with a view open (the headless page or a tab a person opened) it asks that view for the state it holds and returns `source: "live"`; with none open, or none answering within 2 seconds, it returns the stored copy with `source: "stored"`. The `preview` block is unchanged.
- Fix: a repeat `ui_preview` loads the headless page again, so it shows the current document and state. It returns the same `url`.
- Fix: `ui_interact` refuses every action on a node behind an open modal (`fill`, `choose`, `press`, `hover`, `select`, `focus`, as `click` did) instead of reporting ok.
- Fix: `ui_interact` `choose` takes an option value or label on every choice component (radioField, segmented, selectField); when nothing matches the error lists the values and the labels.
- New: `ui_tree` lists the structure of an app as a nested list: one line per node with its key, component and state path, indented two spaces per level with bullets alternating `-` and `*`, slot nodes marked `[slot]`. `path`, `depth` and `paths: false` narrow it. `rendered: true` lists what the headless page draws instead, so the rows of a list and the cards of a board show with the state paths they have while the app runs (the paths `ui_interact` takes); a node with no box is `(hidden)` and its subtree is counted.
- New: `ui_state_reset` puts an app's state back to its document (`$.data` from the document, `$.app` with no articulation) without running the logic, then starts the logic again.
- New: `ui_logic_trace` returns the last runs of an app's logic: the cause, the changed paths and one event per machine, rule, table or guard whose trigger matched, with the outcome (fired, failed, debounced, already-fired, unchanged, parent-removed, other-state, condition, refused) and the writes.
- New: `ui_state_set` takes `logic: false` to write a value past the guards with no rule firing.
- New: `ui_state_get` takes `path` to read one part of the state and shortens `data:` URIs and long strings unless `full: true`.
- New: `ui_interact` has `choose` (a radio option by value or label), `focus`, `key` (a key on whatever has focus, no path) and `drag` (onto the node whose path is `value`; both ends are scrolled into view before the button goes down, since a board reads its column boxes when a drag starts). An action whose element was re-rendered while it ran is tried again instead of failing with "not attached to the DOM".
- New: `ui_events_read` accepts `cursor` as well as `since`.
- Change: every path argument takes a path with or without the leading `$.` (`ui_app_get`, `ui_outline`, `ui_app_write` and `ui_command` refused `$.app...`, `ui_state_set` refused `data...`). The tool descriptions and server instructions are shorter and correct: `ui_state_get` has no `source` field, `focus` tries the control inside the node first, `drag` needs both ends on screen, `ui_outline` ends with the logic.
- New: `ui_validate` warns `SUI-VIEWPORT-NARROW` for a page whose side nav never collapses (`navBreakpoint` 0).
- Fix: a stored record collection (`records`, `items` of a record view) replaces the document's records in the live view instead of merging into them, so records a query left out do not come back.
- Change: `logic.failed` events and the server log name the unit with `kind` and `name` (was `machine`).

- New: logic epic 2 in Full mode. The authority gives the logic `$previous` (the value a client change or a tool write replaced) and runs the `after` and `debounce` timers on the server. A `call` command runs a procedure of the new `procedures` option of `startServer` and `createServices`, or is queued as a `logic.call` event (`{ id, name, payload }`) for `ui_events_read`; the new tool `ui_call_answer` answers it (`not-waiting` when none waits). At most 100 calls wait per app. `ui_outline` lists decision tables with their rows, and shows `after`, `was`, `debounce` and the `call` target. The server instructions describe tables, timers and calls.
- New: app logic in Full mode. Each app's authority runs the document's `logic` (`AppLogic`): a client change runs it after it is applied, guard rules refuse a client change before (the view gets `sync.rejected`), `ui_state_set` asks the guards and runs the logic too, and a transition's writes reach the views as one `changes` message. `$.app` is read as the document's value with the shape defaults under the authority's sparse value. `notify` and `logic.failed` reach the views as app events; `emit` and failures are queued for `ui_events_read`. A value a guard refuses is `logic-guard` from `ui_state_set`.
- New: `ui_outline` of the root ends with the logic: each machine with its current state and transitions, then the rules and guards. The server instructions describe the logic.
- Depends on `@punyts/state-sync` ^0.8.0.
- Fix: the runtime errors a view reported stop showing once their cause is gone. The view counts its loads (a mount, or a new revision rendered in place) and sends the count with its `ready`, `rendered` and `errors` reports. A `ready` or `rendered` report keeps only that view's errors from that load on, since each view reports again what the document still causes. `errors.json` stores each error with its view and load and still reads the older format.
- New: `ui_state_set` takes `remove: true` instead of `value` to remove an entry under `$.data`, such as a deleted record. The authority applies a `delete` change, so every open view drops the record; a `null` value left an empty row behind and there was no other way to remove a record short of rewriting its whole map. A missing entry and `$.data` itself are refused (`unknown-path`), and `value` with `remove` is an `invalid-argument`.
- Fix: `ui_screenshot` of a modal or drawer by its path shows the dialog. The host is `display: contents`, so it has no box and the shot was refused as `not-rendered` while the modal was open; the shot now takes the first drawn element of the host's shadow root.
- Fix: a `ui_interact` click or hover on a node behind an open modal dialog fails with "is behind an open modal dialog" instead of a bare 5 s Playwright timeout.

- New: `--statenet <url>` (`STATEUI_MCP_STATENET`) keeps the app state in a `@punyts/statenet`: each app's authority loads its namespace from the statenet and relays every accepted change to it, with the change ids, so a restarted server picks the state up again. `$.server` is relayed encrypted as `$.sealed`.
- New: `--secret-key-file` (`STATEUI_MCP_SECRET_KEY_FILE`, or the key in `STATEUI_MCP_SECRET_KEY`) sets the key that encrypts `$.server` at rest; an app whose state has `$.server` without a key fails with a message that names the options. The tools and the app API never read `$.server`.
- New: Persisted apps. `ui_app_create` takes `sync: "persisted"`: the state lives only in the statenet (seeded from the document's `data`), the page's sync client connects to the statenet directly and the server socket carries only the view frames; `ui_state_set` is refused (`persisted-app`). Creating one without a statenet is refused (`no-statenet`). `app.json` has `sync` for these apps, and the app API returns `sync`.
- Change: the live view syncs the app state over a WebSocket with `@punyts/state-sync` (Full mode). `GET /apps/:appId/events` (server-sent events) and the `state`, `emit` and `snapshot-reply` reports are gone; `GET /apps/:appId/sync` carries the sync protocol and the view messages. Each app has an authority whose state, sync revision and change log are `state.json`; it starts from the document's `data` and creates missing parents, since `$.app` holds only the articulation. A view keeps its state, its unsent changes and the document in `localStorage`, opens and takes changes offline and sends them when the socket is back; two views of one app see each other's changes at once. The host script is bundled with esbuild (`scripts/build-host.mjs`).
- Change: `ui_state_set` writes through the authority and no longer raises the document revision; `ui_state_get` returns `state` (no `source` or `snapshot`), the authority's state. Runtime-computed values (a formatted `shown`, a measured size) are no longer saved.
- Fix: the live view shows in browsers that refuse a frame with an opaque origin. Some embedded browsers (such as the browser pane of the Claude desktop app) blocked the `sandbox="allow-scripts"` frame, so the page stayed on "Loading…". The runtime page, bundle and stylesheet are now served from a second origin, the runtime port (`--runtime-port`, `STATEUI_MCP_RUNTIME_PORT`, default the next port, 4101), and the frame is sandboxed with `allow-scripts allow-same-origin`: it keeps that origin, which is not the page's, so it still cannot reach the page. The host page allows frames only from the runtime origin, the runtime page allows only the host page to frame it, both by the host name the page was opened with, and the host posts to and accepts messages from the runtime origin only. The main port no longer serves `/runtime/*`.

- Fix: `ui_state_set` of a new key (a new record, a new object under `data`) reaches the open views. The host wrote the leaves of the new value, which the store refuses without their parent, and the next snapshot of the view then dropped the key from the stored state. A new key is now written whole.
- Fix: `ui_screenshot` of a node that is rendered but not visible (such as the body of a closed modal) answers `not-rendered` at once. It waited 30 s for the node to show and then failed with `internal-error` and the raw Playwright log. A visible node that never settles now fails after 5 s, also as `not-rendered`.
- Fix: the runtime page in the frame has a stylesheet (`/runtime/runtime.css`). The browser's 8 px body margin framed every app in white, in a dark theme too, and the root component was only as tall as its content; it now fills the frame and paints its own background to the edges.
- Fix: `ui_state_set` writes only the path it set into the open views. The views diffed the whole stored snapshot, which also holds runtime properties a view reported earlier (a formatted `shown`, a measured size); when the view's later reports lost to quicker tool writes, those stale values were written back over what the view had computed, so a stat bound to a linked number kept its old text. The state message now names the written path, the view replaces only that path (removing keys the new value no longer has), and the host plans the next write on its own copy until the view reports again. A live `ui_state_get` is answered after a ping round trip to the runtime, so it includes every write the view was sent.

## 0.1.0

- First version: a standalone MCP server for building StateUI apps, ported from the `ui-builder` bounded context of AI Minion for one local user (no workspaces, users, approval policy or Postgres).
- The 16 `ui-builder` tools with the same names, arguments, results and error codes: `ui_components_list`, `ui_component_get`, `ui_icons_list`, `ui_tokens_list`, `ui_app_create`, `ui_app_list`, `ui_app_get`, `ui_validate`, `ui_outline`, `ui_state_get`, `ui_app_write`, `ui_state_set`, `ui_preview`, `ui_command`, `ui_file_read` and `ui_app_delete`. `ui_app_list` has no `ownerId`.
- New tools: `ui_screenshot` (PNG image of the page or of one node, with viewport size and theme mode), `ui_interact` (click, fill, press, hover and select by node state path) and `ui_events_read` (the `emit` events the views raised, with a cursor, at most 500 per app).
- `ui_preview` opens a headless Chromium page of the app and returns `{ appId, revision, url, rendered, errors }`; `ui_state_get` reads the state live from an open view (`source: "live"`) and falls back to the stored snapshot; `ui_command` is delivered to every open view, the headless page included.
- The working-loop guidance of `ui-builder` is in the server `instructions` and in the descriptions of `ui_components_list` and `ui_app_create`.
- Storage as one folder of JSON files per app under `--data-dir` (default `./data`), written atomically, one writer at a time per app, with the key order of `children` and keyed data maps kept.
- Transports: streamable HTTP with sessions at `/mcp` (`--port`, default 4100, `--host`, default `127.0.0.1`) and stdio (`--stdio`; the HTTP server still listens and all logs go to stderr).
- Browser endpoint: `GET /` lists the apps; `GET /apps/:appId` runs an app with the content-hashed StateUI runtime bundle in a sandboxed iframe and follows writes, state sets, commands and theme or locale switches over server-sent events; uploads from a `fileField` go to `POST /apps/:appId/files` (10 MiB, the ui-builder type rules). The pages have a strict Content-Security-Policy and the `Host` and `Origin` headers are checked.
