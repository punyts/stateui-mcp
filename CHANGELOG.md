# Changelog

## Unreleased

- New: app logic in Full mode. Each app's authority runs the document's `logic` (`AppLogic`): a client change runs it after it is applied, guard rules refuse a client change before (the view gets `sync.rejected`), `ui_state_set` asks the guards and runs the logic too, and a transition's writes reach the views as one `changes` message. `$.app` is read as the document's value with the shape defaults under the authority's sparse value. `notify` and `logic.failed` reach the views as app events; `emit` and failures are queued for `ui_events_read`. A value a guard refuses is `logic-guard` from `ui_state_set`.
- New: `ui_outline` of the root ends with the logic: each machine with its current state and transitions, then the rules and guards. The server instructions describe the logic.
- Depends on `@punyts/state-sync` ^0.8.0.
- Fix: the runtime errors a view reported stop showing once their cause is gone. The view counts its loads (a mount, or a new revision rendered in place) and sends the count with its `ready`, `rendered` and `errors` reports. A `ready` or `rendered` report keeps only that view's errors from that load on, since each view reports again what the document still causes. `errors.json` stores each error with its view and load and still reads the older format.
- New: `ui_state_set` takes `remove: true` instead of `value` to remove an entry under `$.data`, such as a deleted record. The authority applies a `delete` change, so every open view drops the record; a `null` value left an empty row behind and there was no other way to remove a record short of rewriting its whole map. A missing entry and `$.data` itself are refused (`unknown-path`), and `value` with `remove` is an `invalid-argument`.
- Fix: `ui_screenshot` of a modal or drawer by its path shows the dialog. The host is `display: contents`, so it has no box and the shot was refused as `not-rendered` while the modal was open; the shot now takes the first drawn element of the host's shadow root.
- Fix: a `ui_interact` click or hover on a node behind an open modal dialog fails with "is behind an open modal dialog" instead of a bare 5 s Playwright timeout.

- New: `--statenet <url>` (`STATEUI_MCP_STATENET`) keeps the app state in a `@punyts/statenet`: each app's authority loads its namespace from the statenet and relays every accepted change to it, with the change ids, so a restarted server picks the state up again. `$.server` is relayed encrypted as `$.sealed`.
- New: `--secret-key-file` (`STATEUI_MCP_SECRET_KEY_FILE`, or the key in `STATEUI_MCP_SECRET_KEY`) sets the key that encrypts `$.server` at rest; an app whose state has `$.server` without a key fails with a message that names the options. The tools and the app API never read `$.server`.
- New: Persisted apps. `ui_app_create` takes `sync: "persisted"`: the state lives only in the statenet (seeded from the document's `data`), the page's sync client connects to the statenet directly and the server socket carries only the view frames; `ui_state_set` is refused (`persisted-app`). Creating one without a statenet is refused (`no-statenet`). `app.json` has `sync` for these apps, and the app API returns `sync`.
- Change: the live view syncs the app state over a WebSocket with `@punyts/state-sync` (Full mode). `GET /apps/:appId/events` (server-sent events) and the `state`, `emit` and `snapshot-reply` reports are gone; `GET /apps/:appId/sync` carries the sync protocol and the view messages. Each app has an authority whose state, sync revision and change log are `state.json`; it starts from the document's `data` and creates missing parents, since `$.app` holds only the articulation. A view keeps its state, its unsent changes and the document in `localStorage`, opens and takes changes offline and sends them when the socket is back; two views of one app see each other's changes at once. The host script is bundled with esbuild (`scripts/build-host.mjs`).
- Change: `ui_state_set` writes through the authority and no longer raises the document revision; `ui_state_get` returns `state` (no `source` or `snapshot`), the authority's state. Runtime-computed values (a formatted `shown`, a measured size) are no longer saved.
- Fix: the live view shows in browsers that refuse a frame with an opaque origin. Some embedded browsers (such as the browser pane of the Claude desktop app) blocked the `sandbox="allow-scripts"` frame, so the page stayed on "Loading…". The runtime page, bundle and stylesheet are now served from a second origin, the runtime port (`--runtime-port`, `STATEUI_MCP_RUNTIME_PORT`, default the next port, 4101), and the frame is sandboxed with `allow-scripts allow-same-origin`: it keeps that origin, which is not the page's, so it still cannot reach the page. The host page allows frames only from the runtime origin, the runtime page allows only the host page to frame it, both by the host name the page was opened with, and the host posts to and accepts messages from the runtime origin only. The main port no longer serves `/runtime/*`.

- Fix: `ui_state_set` of a new key (a new record, a new object under `data`) reaches the open views. The host wrote the leaves of the new value, which the store refuses without their parent, and the next snapshot of the view then dropped the key from the stored state. A new key is now written whole.
- Fix: `ui_screenshot` of a node that is rendered but not visible (such as the body of a closed modal) answers `not-rendered` at once. It waited 30 s for the node to show and then failed with `internal-error` and the raw Playwright log. A visible node that never settles now fails after 5 s, also as `not-rendered`.
- Fix: the runtime page in the frame has a stylesheet (`/runtime/runtime.css`). The browser's 8 px body margin framed every app in white, in a dark theme too, and the root component was only as tall as its content; it now fills the frame and paints its own background to the edges.
- Fix: `ui_state_set` writes only the path it set into the open views. The views diffed the whole stored snapshot, which also holds runtime properties a view reported earlier (a formatted `shown`, a measured size); when the view's later reports lost to quicker tool writes, those stale values were written back over what the view had computed, so a stat bound to a linked number kept its old text. The state message now names the written path, the view replaces only that path (removing keys the new value no longer has), and the host plans the next write on its own copy until the view reports again. A live `ui_state_get` is answered after a ping round trip to the runtime, so it includes every write the view was sent.

## 0.1.0

- First version: a standalone MCP server for building StateUI apps, ported from the `ui-builder` bounded context of AI Minion for one local user (no workspaces, users, approval policy or Postgres).
- The 16 `ui-builder` tools with the same names, arguments, results and error codes: `ui_components_list`, `ui_component_get`, `ui_icons_list`, `ui_tokens_list`, `ui_app_create`, `ui_app_list`, `ui_app_get`, `ui_validate`, `ui_outline`, `ui_state_get`, `ui_app_write`, `ui_state_set`, `ui_preview`, `ui_command`, `ui_file_read` and `ui_app_delete`. `ui_app_list` has no `ownerId`.
- New tools: `ui_screenshot` (PNG image of the page or of one node, with viewport size and theme mode), `ui_interact` (click, fill, press, hover and select by node state path) and `ui_events_read` (the `emit` events the views raised, with a cursor, at most 500 per app).
- `ui_preview` opens a headless Chromium page of the app and returns `{ appId, revision, url, rendered, errors }`; `ui_state_get` reads the state live from an open view (`source: "live"`) and falls back to the stored snapshot; `ui_command` is delivered to every open view, the headless page included.
- The working-loop guidance of `ui-builder` is in the server `instructions` and in the descriptions of `ui_components_list` and `ui_app_create`.
- Storage as one folder of JSON files per app under `--data-dir` (default `./data`), written atomically, one writer at a time per app, with the key order of `children` and keyed data maps kept.
- Transports: streamable HTTP with sessions at `/mcp` (`--port`, default 4100, `--host`, default `127.0.0.1`) and stdio (`--stdio`; the HTTP server still listens and all logs go to stderr).
- Browser endpoint: `GET /` lists the apps; `GET /apps/:appId` runs an app with the content-hashed StateUI runtime bundle in a sandboxed iframe and follows writes, state sets, commands and theme or locale switches over server-sent events; uploads from a `fileField` go to `POST /apps/:appId/files` (10 MiB, the ui-builder type rules). The pages have a strict Content-Security-Policy and the `Host` and `Origin` headers are checked.
